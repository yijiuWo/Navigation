三、部署方式（务必分清，别弄混）

用的是什么：Qoder Sites 云端直传。
不是 GitHub Pages，也不是 push 后自动发布。git push 只同步代码，和线上是否更新无关。

具体流程（以后每次更新都照这个走）：
  1. 本地 git archive HEAD 导出到仓库外的临时目录（Linux 用 /tmp/zenmap-dist；
     Windows Git Bash 同路径），只保留 index.html、map.html、assets/，共 25 个文件
     - 不带 .tmp/、AGENTS.md、txt、package*.json
     - 不要直接上传仓库目录，也不要把 dist 提交进仓库
  2. prepare_site：每次新 actionId，带已有 projectId
     01a21628-550f-7b1c-81a3-d7158f8dd352，projectRoot/webDirectory 不变
     不要再带 createNewSite / slug / subdomain
  3. publish_site → 轮询 get_publish_status 到 published:true
  4. 站点访问权限保持公开（无登录墙、无密码）

已知坑（一定会再遇到）：
- 校园网 DNS（222.22.80.1）对 aliyuncs.com 整个域解析失败，上传报 EAI_AGAIN
- 临时办法：管理员权限在 hosts 加一行
    39.156.229.137 cn-qoder-sites.oss-cn-beijing.aliyuncs.com
  flushdns 后重试上传；发布成功立刻删掉该行再 flushdns，不要常驻
- 更稳的办法是换能正常解析的网络（手机热点等），但切换网络可能中断当前会话
- 另：github.com 域名单独不通（curl 000，api.github.com 正常 200）时，push 会失败而部署不受影响；
  两者走不同链路，不要互相替代，也不要用改 hosts 的方式绕 GitHub

地址格式：平台固定为 站点名-随机后缀.qoder.zone，不是 zenmap.qoder.site，属正常规则。

其他：平台会在每个 HTML 末尾注入 watermark 脚本（data-qoder-watermark，指向 qoder.cn），
页面体积因此比本地大，属正常；不要删、也不要当成自己的代码。
