三、部署方式（必须分清，别弄混）

用的是什么：Qoder Sites 云端直传。不是 GitHub Pages，push 与线上是否更新无关。

流程（每次更新照这个走）：
  1. git archive HEAD 导出到仓库外的临时目录，只保留 index.html、map.html、assets/，共 25 个文件
     - 不带 .tmp/、AGENTS.md、任何 txt、.ZenMap.qoder.site、package*.json
     - 不要直接上传仓库目录，也不要把 dist 提交进仓库
  2. prepare_site：每次新 actionId，带已有 projectId
     01a21628-550f-7b1c-81a3-d7158f8dd352，projectRoot/webDirectory 不变
     不要再带 createNewSite / slug / subdomain
  3. publish_site → 轮询 get_publish_status 到 published:true
  4. 站点访问权限保持公开

发布后核对（重要）：
- 比 map.js / zen.css / drive.js / zen-tw.css 的字节数，这些是原样上传的
- **不要直接比 map.html / index.html 的总字节**：平台会注入 watermark 脚本，
  2026-11-27 实测注入量 57042 字节（18307 → 75349、11229 → 68271）。
  要比就对前缀做 cmp（本地包与线上前 18292 字节逐字节一致）。
  若注入量明显变化，说明平台改了逻辑，需重新记基线

已知坑：
- 校园网 DNS（222.22.80.1）解析不了 aliyuncs.com，上传报 EAI_AGAIN。
  临时办法：管理员权限在 hosts 加
    39.156.229.137 cn-qoder-sites.oss-cn-beijing.aliyuncs.com
  flushdns 后重试；发布成功立刻删掉该行再 flushdns，不要常驻
- 更稳的办法是换能正常解析的网络（手机热点等），但切换网络可能中断会话
- github.com 单独不通（curl 000，api.github.com 正常）时，push 会失败而部署不受影响，
  两条链路不要互相替代，也不要用改 hosts 的方式绕 GitHub
- 工具会在仓库根写 .ZenMap.qoder.site（约 31KB，含各 id 与 index.html 快照），
  每次发布重写，属于工具状态：已加入 .gitignore（*.qoder.site），不提交、不手改、不删

地址格式：站点名-随机后缀.qoder.zone，不是 zenmap.qoder.site，属正常规则。

五、已知边界（不是待办，是评委问到时的口径）

1. 公交态不显示转向引导卡，沿用「下一站」提示；驾车与步行有完整转向引导
2. 转向里程用 OSRM step 距离累加，本地投影用 haversine 累加，长路线约 30m 偏差（16.4km 实测 28m）
3. 出入口面板按方向只展示一侧：上车站优先，两个都是地铁站时下车站的口不在列表里
4. 环岛在 OSRM 未给 maneuver.exit 时回退为「第 1 个出口」
5. 弱网或断网时瓦片可能白，无离线缓存
6. iOS 硬件静音拨片会静音 Web Speech，网页无法检测，已在导航横幅提示
7. 安全评分为启发式估算、风险数据为演示样本，界面已注明

赛后可做（不影响本次评分）：骑行模式、充电桩/停车场 POI、
安全 vs 最快路线权衡、实时路况接入、弱网瓦片缓存、配色继续统一卡片与图例色阶。
